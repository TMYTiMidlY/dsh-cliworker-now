# Spec Delta

## ADDED Requirements

### Requirement: 未完成准入与旧历史缺绑定分层诊断
缺少账号绑定的Worker SHALL 保持不可用于受保护目录、选型或prompt；诊断 MUST 按可核验生命周期区分排队准备、首次准入失败和真正旧历史缺绑定。无法证明来源时只说明证据缺失，不推断账号退出、无额度或已执行成功。不得自动绑定当前账号、创建替代Worker或重发原任务。

#### Scenario: 新任务仍在排队准备
- **WHEN** 当前Worker有可核验的待准入状态且账号绑定尚未完成
- **THEN** 返回PENDING_ADMISSION及等待/显式CLI目录查询提示，不标成旧历史、登录失败或厂商额度耗尽

#### Scenario: 新任务首次准备已失败
- **WHEN** 可证明新Worker在建立账号绑定前准备超时或失败，并已结束本次准入
- **THEN** 提示该次准入未完成及绑定尚未建立，保留实际失败与run；不声称它是升级前历史，不查询另一账号或发送prompt

#### Scenario: 真正旧历史缺少绑定
- **WHEN** 已有旧会话没有可核验的原账号绑定
- **THEN** 保留只读历史并维持原有拒绝，不自动收养当前账号或迁移Native会话

#### Scenario: 生命周期证据不足
- **WHEN** 历史缺绑定且不能证明其属于首次准入失败或旧版本
- **THEN** 返回中性的账号证据不足诊断，不从时间、标签或其他父会话猜身份

#### Scenario: 停止与清理不依赖重新借号
- **WHEN** 缺绑定或准入失败的记录仍有已拥有范围需停止
- **THEN** 仍按原进程所有权等待实际清理，不为停止查询或绑定另一个账号
