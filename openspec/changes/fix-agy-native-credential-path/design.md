## Context

AGY 状态查询使用 `localAccountIdentity`；模型查询在 `discoverAgyAccountModels` 内调用同一身份读取器。授权版本另由 `readCliAccountBinding` 读取本地材料。两条路径复制旧文件名，需一并修正。本机正确文件的存在性及可读性已核对，未将真实秘密写入开发目录。

## Goals / Non-Goals

目标：在不修改原生登录态的情况下，让文件认证各入口选择同一当前来源；保持拒绝不安全文件、退出/换号检测及不泄漏认证材料。

非目标：不凭文件存在声称远端可调用；不实现系统 keyring 新协议、不迁移旧凭据、不绕过原有授权检查、不改变 Windows Credential Manager。

## Decisions

1. 添加纯路径函数 `agyAccountPath(home)`，默认使用当前 home，返回 `.gemini/antigravity-cli/antigravity-oauth-token`。身份与绑定共享该函数，不通过搜索其他工具目录获取认证。
2. 不做旧 jetski 文件兜底。原生文件被删除或损坏时即使旧文件存在也必须拒绝，避免使用与 CLI 实际来源不一致的账号。旧版文件认证部署可能需更新 CLI，不能通过复制 token 掩盖协议差异。
3. 读取及材料处理复用原实现：有界、只读、不跟随链接、比较打开前后 inode/大小/mtime、退出后清零缓冲；Windows 分支不改变。
4. 测试仅使用合成 home 和假 token，覆盖状态、模型预检与绑定。不会自动执行真实模型、刷新 token 或写原生认证。

## Risks / Trade-offs

- 仅支持旧 jetski 文件的安装不再被错误地视为当前 CLI 登录；不猜测不同版本的来源优先级。
- 当前原生 JSON 字段与原解析器是否完全兼容需要后续脱敏本地验证，不能把路径修复表述为真实模型验收通过。
- 新来源根目录改变会影响旧账号绑定；已有成功绑定的历史不能自动改绑，原有历史仍保留。

## Migration Plan

先在 fork 中执行关联测试、类型检查与隔离构建。打包后由用户确认替换安装，保留配置和历史备份，不改包名/版本，不发布。失败时恢复原安装包，原生登录文件始终不动。

## Open Questions

真实账号状态、目录与用户选定模型调用需在安装替换授权及 CLI 选型后验收；当前阶段只声明实际通过的离线检查。
